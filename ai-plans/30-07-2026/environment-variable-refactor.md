# Замена жёстко закодированного домена на переменные окружения

## Контекст

В проекте встречаются жёстко закодированные значения доменных имён в скриптах деплоя:
- `deploy.sh` - содержит `DOMAIN="grigoryvolchok.ru"` на строке 11
- `infra/renew-certificate.sh` - содержит `DOMAIN="grigoryvolchok.ru"` на строке 8

Это затрудняет использование проекта на других доменах и делает конфигурацию менее гибкой.

## Цель изменения

Заменить жёстко закодированные доменные имена на переменные окружения, чтобы:
1. Упростить использование проекта на разных доменах
2. Обеспечить гибкость конфигурации для локальной разработки и серверной среды
3. Следовать лучшим практикам управления конфигурацией

## Предлагаемое решение

### Использование переменных окружения с проверкой наличия

Изменить скрипты для чтения доменного имени из переменной окружения с проверкой её наличия:

```bash
# В deploy.sh
if [ -z "$DOMAIN" ]; then
  echo "Ошибка: переменная окружения DOMAIN не установлена"
  exit 1
fi

# В infra/renew-certificate.sh  
if [ -z "$DOMAIN" ]; then
  echo "Ошибка: переменная окружения DOMAIN не установлена"
  exit 1
fi
```

## Реализация

### Шаги по изменению:

1. Отредактировать `deploy.sh` - заменить жёстко закодированное значение на переменную с дефолтным значением
2. Отредактировать `infra/renew-certificate.sh` - аналогично
3. Добавить описание в README о необходимости установки переменных окружения при необходимости

## Проверка

Для проверки работы изменений необходимо:
1. Выполнить скрипты в локальной среде (переменная не установлена) - должны использовать значение по умолчанию
2. Выполнить скрипты с установленной переменной окружения - должны использовать пользовательское значение
3. Убедиться, что все функциональности работают корректно
